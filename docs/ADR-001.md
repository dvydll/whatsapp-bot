# ADR-001: Stack Tecnológico y Arquitectura del Proyecto

> Architecture Decision Record  
> Fecha: 2026-04-27

## Resumen

Este ADR documenta las decisiones de arquitectura tomadas durante la fase de planificación de WhatsAppBot, incluyendo stack tecnológico, arquitectura de software y sistema de plugins.

---

## Decisiones Tomadas

### 1. Gestor de Paquetes

| Decisión | Alternativas Consideradas | Justificación |
|---------|---------------------------|--------------|
| **pnpm** | npm, yarn, bun | Lock preciso, instalador rápido, mejor gestión de workspaces |

### 2. Runtime

| Decisión | Alternativas Consideradas | Justificación |
|---------|---------------------------|-------------|
| **Node.js 20+ LTS** | 18.x, 22.x | Version LTS estable con loadEnvFile nativo y fetch API |

### 3. Lenguaje

| Decisión | Alternativas Consideradas | Justificación |
|---------|---------------------------|-------------|
| **TypeScript** | JavaScript puro | Tipado estático previene errores en runtime, mejor DX con IDE |

### 4. Logging

| Decisión | Alternativas Consideradas | Justificación |
|---------|---------------------------|-------------|
| **Pino** | Winston, Bunyan, console | Logging estructuradoJSON, performant, estándar en producción |

### 5. Validación

| Decisión | Alternativas Consideradas | Justificación |
|---------|---------------------------|-------------|
| **Zod** | Yup, Joi, plain objects | Tipado inferido automático, schemassign |

### 6. Testing

| Decisión | Alternativas Consideradas | Justificación |
|---------|---------------------------|-------------|
| **Vitest** | Jest, Mocha, AVA | API compatible con Jest, más rápido, built-in watch mode |

### 7. HTTP Client

| Decisión | Alternativas Consideradas | Justificación |
|---------|---------------------------|-------------|
| **Node.js fetch nativo** | axios, got, node-fetch | No requiere dependencia adicional desde Node 18+ |

### 8. Environment Variables

| Decisión | Alternativas Consideradas | Justificación |
|---------|---------------------------|-------------|
| **Node.js loadEnvFile** | dotenv, env-var | Nativo desde Node 20.11, sin dependencia |

### 9. Docker

| Decisión | Alternativas Consideradas | Justificación |
|---------|---------------------------|-------------|
| **Docker + docker-compose** | Kubernetes, Podman | Despliegue reproducible, estándar en producción |

### 10. Arquitectura de Software

| Decisión | Alternativas Consideradas | Justificación |
|---------|---------------------------|-------------|
| **Screaming Architecture + Clean Architecture** | Hexagonal, layers, MVC | Separación clara de responsabilidades, independencia de features, testabilidad |

### 11. Sistema de Plugins

| Decisión | Alternativas Consideradas | Justificación |
|---------|---------------------------|-------------|
| **Plugin System con Interface** | Hardcoded, dynamic require | Extensibilidad sin modificar código core, carga bajo demanda |
